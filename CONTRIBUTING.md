# Contributing

Useful additions include clearer instructions, corrected links, tested setup notes and small examples you made yourself.

For a correction, describe what you tried, what happened and the file or passage you would change. State the tool version if it affects the result. A proposed improvement and a tested workflow should be clearly distinguished.

Submit only material you have permission to share publicly. Do not upload credentials, personal recordings, private campaign briefs, client files, paid asset libraries or private workspace exports. If an example needs an external asset, link to its legitimate source and explain the requirements.

Keep guides simple, specific and easy to follow. Explain a tool through the job it does. Avoid unsupported promises about guaranteed quality, earnings, virality or identical AI outputs.

## Adding a collection

Build around one useful outcome, such as editing a video in a chosen style. Give the collection one starting page that includes:

1. What someone will be able to do and who it is for.
2. What they need before starting, including tool access or costs.
3. A short sequence of steps and links to the required files.
4. What to check in the result and what to try if it goes wrong.
5. The resource version, review date and what was actually tested.

Put a collection's guide and supporting documents in `resources/<outcome>/`. Keep reusable fill-in files in `templates/<template-name>/` and link to them. Reuse an existing template when it already does the job.

Add the collection to `RESOURCES.md` under its main purpose: Plan content, Create content, Publish content, or Build your system. Add video links when published; a guide must also work without watching the video. Do not add empty category folders or duplicate a collection for every new video.

For a skill or runnable tool, include installation, required permissions, supported setup and a small example someone can verify. Label untested instructions clearly. Review any third-party redistribution rights before including files; public availability alone does not establish permission to redistribute them.
